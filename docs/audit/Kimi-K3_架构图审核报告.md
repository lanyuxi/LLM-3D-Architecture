## 二、实质性错误（4 处，均已修正）

### E1 许可证张冠李戴

| 项 | 内容 |
|---|---|
| 图中原写 | 「修改版 MIT」 |
| 官方口径 | 权重与代码均以 **Kimi K3 License** 发布（自定义许可：MaaS 业务 12 个月营收 > $20M 需另签协议；月活 > 1 亿或月营收 > $20M 的产品需显著展示 "Kimi K3"）。**modified MIT 是上一代 K2 的措辞** |
| 依据 | 官方 README §7：「Both the code repository and the model weights are released under the **Kimi K3 License**」 |
| 修正 | header 副标题 + 节点 15 三处 + 大白话文案，全部改为 Kimi K3 License（并注明「不是 MIT」） |

### E2 词表数值误读

| 项 | 内容 |
|---|---|
| 图中原写 | 「词表 160,000」 |
| 官方口径 | 模型卡写 **160K**，而 `config.json` 的 `vocab_size` = **163,840** —— 即 160×1024，不是十进制 16 万 |
| 修正 | 节点 03 / 14 / 15 与大白话文案共 6 处改为 163,840，并注明「官方口径写作 160K」 |

### E3 量化范围与官方相反

| 项 | 内容 |
|---|---|
| 图中原写 | 「输出头随整套权重一起以 MXFP4 提供」 |
| 官方口径 | `config.json` 的 `quantization_config.ignore` 明确排除 `self_attn`、`shared_experts`、稠密 MLP 投影、**`lm_head`**、`vision_tower`、`mm_projector`。**只有 896 个路由专家的权重被压到 4 位** |
| 修正 | 节点 14 三处 + 节点 12 四处 + 左列 A8 对照文案，统一改为「4 位只作用于路由专家，输出头等保持 bfloat16」 |

### E4 AttnRes 数字挂错实体

| 项 | 内容 |
|---|---|
| 图中原写 | 「官方在 48B 模型上的消融显示，该改动带来约 1.25 倍训练效率提升，额外计算不到 2%」 |
| 官方口径 | ① **1.25×** 来自 AttnRes 论文在 **1.94 亿–5.28 亿激活参数**区间做的 scaling law 拟合，不是 48B 模型消融；② 官方对 K3 的「2%」指的是**推理延迟开销**，训练侧官方称「可忽略」，未见「额外计算 < 2%」的表述 |
| 修正 | 改为准确归属：scaling law 拟合区间 + 官方对 K3 的延迟口径 |

## 六、经核实确认无误的部分

**核心架构参数**（官方 README Model Summary + config.json + 技术报告三源互证）：

- 2.8T 总参数 / 104B 激活；93 层；hidden 7,168；词表 163,840
- **69 KDA + 24 Gated MLA**（3:1 混合 + 末尾补 1 层全局层）
- 896 路由专家 / 每 token 激活 16 / **2 个共享专家** / 激活率约 1.8%
- latent 3,584（= hidden 的 0.5×）、每专家中间维度 3,072
- **NoPE**：完全无显式位置编码
- KDA：delta-rule + 通道级遗忘门、固定大小递归状态、`gate_lower_bound = −5`、16-token tile 内衰减落在 (−80, 0)、对角块走 Tensor Core
- AttnRes：伪查询跨深度注意力、块内求和、开销 O(Ld)→O(Nd)、块大小 12
- SiTU-GLU：β₁=4 / β₂=25，输出上界 100（由 β₁·β₂ 推得）
- Quantile Balancing：按分位数直接定路由偏置、无辅助损失
- MXFP4 权重 + MXFP8 激活、**从 SFT 阶段即 QAT**
- MoonViT-V2：401M / 27 层 / patch 14，从零用 next-token prediction 训练
- 思考档位发布默认 max、low/high 后续开放（节点 13 引用的英文字句与官方博客逐字一致）
- 扩展效率相对 K2 约 2.5×；2026-07-27 开源权重；同步开源 MoonEP / FlashKDA / AgentEnv

**补充的官方细节**：93 层里**第 1 层是稠密 MLP**、其余 92 层才是 MoE（`first_k_dense_replace = 1`）—— 已在节点 09 补充。

## 七、审核局限

1. **技术报告 PDF 未能直接解析**：报告原文（AttnRes 分块原话、SiTU 的 β 值、`g_min = −5`、O(Ld)→O(Nd)）通过官方 README、开放日公告与多份逐字引用该 PDF 的来源交叉验证；签字级确认建议人工打开 PDF 对应段落。
2. **HF 模型卡页面抓取失败**：改以官方 GitHub README 同一张 Model Summary 表为准，并以搜索索引中的模型卡副本交叉验证。
3. **E4 中「2%」的准确措辞**：官方明确可查的是「推理延迟开销 < 2%」「训练额外开销可忽略」；若报告某页另有表述，以 PDF 为准。
4. **每层 896 个专家的逐层归属**：官方只给总数 896（对比 K2 的 384），按 K 系列一贯结构推断每 MoE 层各持 896，与官方口径不冲突但严格说属推断。
5. **厂商自测口径**：性能与效率数字均为官方自测，非第三方复现。
