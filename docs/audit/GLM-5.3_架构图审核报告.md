## 二、实质性错误（6 处，均已修正）

### A1 索引器机制描述反了（最严重）

| 项 | 内容 |
|---|---|
| 图中原写 | 「两级筛选：先粗粒度**块**选择，再细粒度 token 选择」 |
| 官方口径 | DSA = 轻量索引器 + **token 级细粒度选择**，**恰以「不做块选择」为定义特征**。智谱技术报告：「其轻量级索引器在不丢弃任何长程依赖的情况下实现 **token 级稀疏性**」；DeepSeek-V3.2 论文：「a lightning indexer and a **fine-grained token selection** mechanism」 |
| 判定 | 机制描述错误——写成的是 NSA 那类基于块的方案的机制 |
| 修正 | 改为「token 级细粒度选择，不做「先分块、再选块」的粗粒度近似——这正是 DSA 与基于块的稀疏注意力方案的关键区别」 |

### A2 许可证张冠李戴

| 项 | 内容 |
|---|---|
| 图中原写 | `MIT 开源` |
| 官方口径 | GLM-5.3 使用**自定义的 GLM-5.3 License**：允许本地部署、微调与一般商用；机构及关联方连续 12 个月合计收入超 100 亿美元且对外提供 MaaS 时，须先通过 Z.ai 安全审查。**MIT 属上一代 GLM-5.2**（GLM-5.3-Flash 也仍走 MIT，形成分叉） |
| 修正 | 改为 `GLM-5.3 License`（副标题与指标口径同步） |

### A3 日期挂错事件

| 项 | 内容 |
|---|---|
| 图中原写 | 「2026-08-14 发布」并暗示当日即开源 |
| 官方口径 | 08-14 是**发布/公告日**；官方原文「We will release the weights in **two weeks after launch**」，权重实际 **08-28 开放**（Hugging Face 仓库 Initial commit 0828，Z.ai 宣布 "GLM-5.3 is now open-weight"） |
| 修正 | 改为「2026-08-14 发布 · **权重 08-28 开放**」 |

### A4 / A5 量化范围说错（嵌入表与输出头）

| 项 | 内容 |
|---|---|
| 图中原写 | 节点 02「嵌入矩阵同样参与低精度量化」；节点 13「输出头权重与主干一起量化到 FP8」 |
| 官方口径 | FP8 只覆盖**线性层**（MoE 专家、稠密 MLP、注意力与索引器投影）；**嵌入表与输出头保持 BF16** |
| 修正 | 两处均改为「保持 BF16」「量化只覆盖线性层」 |

### A6 「思考 / 非思考」档位不存在

| 项 | 内容 |
|---|---|
| 图中原写 | 「思考 / 非思考」「可按任务决定是否展开推理」「决定是否输出思考过程」 |
| 官方口径 | 官方文档原文：「GLM-5.3 **always operates with reasoning enabled**… **Disabling reasoning is no longer supported.**」`thinking.type` 只接受 `enabled`；沿用 `disabled` 写法**请求会直接失败**。可调的是 `reasoning_effort` 三档 low / high / max，**默认 max** |
| 修正 | 节点 14 与大白话文案整体重写为「始终启用思考 + 三档强度，默认 max」 |

## 五、经核实确认无误的部分

**架构硬参数**（三源互证：`zai-org/GLM-5.2` config.json、NVIDIA NeMo `GlmMoeDsaConfig`、百度智能云 GLM-5.3 模型概要）：

- 架构标识 `glm_moe_dsa` / `GlmMoeDsaForCausalLM`
- 78 层、hidden 6,144、64 注意力头、词表 154,880
- 256 路由专家 + 1 共享专家，每 token 激活 8 个
- **前 3 层稠密 FFN（`first_k_dense_replace: 3`，中间维度 12,288）**，其余 75 层 MoE
- `moe_intermediate_size` 2,048；总参数 744B / 激活 40B
- 上下文 1,048,576；最大输出 128K
- FP8 E4M3 + block 128×128；RoPE θ = 8,000,000
- 索引器 32 头（`index_n_heads`）、`index_head_dim` 128、top-k 2,048
- `kv_lora_rank` 512、`q_lora_rank` 2,048
- `num_nextn_predict_layers` 1（权重自带 1 层 MTP）

**其余确认无误**：纯文本模型（多模态在 GLM-5.3-Flash）；与 GLM-5.2 同基座、提升来自后训练；MLA「效果对标 GQA、显存更少」；IndexShare 每 4 层共享、省 3/4 索引计算、1M 下 FLOPs ↓2.9×；DSA 两阶段继续预训练；平均接受 3.35 个草稿 token、单流 300+ tokens/s；Z.ai Code Bench +50%；FP8 与 BF16 双版本；2017 对照栏 A1–A9 全部正确。

**开发方点名复核的 8 项**（a–h）：其中 (c) RoPE 作用于全 78 层 ✅、(d) 每 4 层共享与省 75% 自洽 ✅、(g) MLA 描述 ✅、(h) MTP 自带 1 层 ✅、(a) MTP「GLM-5 三层共享 → 5.2/5.3 配置为 1 层」✅；而 (b) 索引器两级筛选 ❌、(e) FLOPs 标签措辞 ⚠️、(f) 日期与许可证 ❌ —— 均已修正。

## 六、审核局限

1. **许可证逐字文本**：Hugging Face `zai-org/GLM-5.3` 仓库多次抓取失败，「非 MIT、改用带营收门槛的 GLM-5.3 License」这一结论由三个独立来源一致记载（鉅亨網、cnBeta、腾讯新闻聚合），并经 Z.ai 公告口径交叉印证，但未直读 LICENSE 原文。
2. **`lm_head` 的 dtype**：`model.embed_tokens` 未量化有多处直接证据；`lm_head` 为 BF16 的判定来自基于官方 FP8 权重的再量化发布（friendli、RedHatAI），非智谱原始仓库直读。
3. **GLM-5 技术报告「80 层」 vs config「78 层」**：官方材料内部不一致。对 GLM-5.3 而言 78 层有模型概要与 config 双重支持，图中写 78 正确，但无法解释 80 的出处。
4. **开发厂商口径**：所有性能数字均为官方自测，非第三方复现。
5. **`index.html` 中 DeepSeek 行**的「CED 非对称编解码器」不在本次审核范围（该模型此前已单独审核）。
