## 一、实质性错误（2 处，已修正）

### E1 把「嵌入与输出头共享权重」写错了（散布 7 处）

| 项 | 内容 |
|---|---|
| 图中原写 | 「嵌入矩阵与输出头是共享权重（tied）」「官方架构图在输入与输出两处都标注了 Embedding (tied)」 |
| 官方口径 | `config.json` 明确 **`"tie_word_embeddings": false`** —— 发布的权重里 embed_tokens 与 lm_head 是**两份独立参数**（HF 镜像 + ModelScope 官方 API 双源一致） |
| 我为什么会错 | 我看到的 **"Embedding (tied)" 标注出自 MiMo-V2-Flash 技术报告的 MTP 分支图**——那里的 "tied" 指的是 **MTP 模块与主干共享** embedding / LM head，推不出「主干自身的输入嵌入与输出头互相共享」。另一个诱导项是建模代码里的 `_tied_weights_keys` 声明，那只是 transformers 的通用写法，实际行为由 `config.tie_word_embeddings` 决定 |
| 修正 | 节点 02 / 14、左列 A8、大白话 02 / 14 共 7 处全部改为「两份独立参数，不共享权重」，并顺带补上官方 config 的词表大小 **152,576** |

### E2 「11 个周期」是算术错误

| 项 | 内容 |
|---|---|
| 图中原写 | 「把 70 层切成 **11 个周期**」「11 个周期，60 + 10 恰好切分」「循环 11 轮」 |
| 算术 | 6:1 对应 **10 组**（10 × 7 = 70）；11 × 7 = 77 > 70，**11 与同句的「恰好切分」自相矛盾** |
| 官方口径 | 官方只表述「interleaved at a **6:1 ratio**」，从未提周期数；config 的 `hybrid_layer_pattern` 恰含 10 个 0、60 个 1 |
| 修正 | 3 处改为「10 组/10 个周期」 |

## 四、确认无误的项

**官方规格表 17 项全部正确**：1.02T 总参、42B 激活、70 层（1 dense + 69 MoE）、10 层全注意力、60 层 SWA、隐藏维度 6144、128 查询头、8 KV 头（GQA）、head dim QK 192 / V 128、384 路由专家、每 token 激活 8、MoE 中间维度 2048、稠密中间维度 16384（仅第 0 层）、SWA 窗口 128、上下文 1M、MTP 3 层、稀疏比 ≈24×

**两模型未串写（我特别在意的点）**：所有对照处均正确 —— V2.5 的 310B/15B、隐藏维度 4096、256 路由专家、KV 头 8(GA)/4(SWA)、48T token 全部标注正确。

**机制与描述**：6:1 混合注意力、SWA 128 窗口、KV ↓7×、可学习 attention sink、MTP triples output speed、三阶段后训练、纯解码器无跨注意力、RMSNorm、RoPE 在注意力内部注入、架构块顺序「RMSNorm → 注意力 → RMSNorm → Sparse MoE」、KV Cache 双池 + SWA-aware 前缀树、3 步 EAGLE 投机解码、SGLang/vLLM 部署方案 —— 全部核对无误。

## 五、审核局限

1. **HF 直连被网络策略阻断**：模型卡全文经多个独立镜像交叉比对（逐字一致），`config.json` 另经 ModelScope 官方 API 复核。
2. **权重上传 HF 的确切时间无法核实**：官方仅称发布同期开源；有个别第三方称 6-29，与官方冲突且无依据。
3. **27T 的构成与 FP8 精度归属**：官方未说明，图中已中性化处理。
4. **SGLang Cookbook 的 license 字段疑为笔误**（写 Apache 2.0）——以小米官方与 HF/ModelScope 为准。
