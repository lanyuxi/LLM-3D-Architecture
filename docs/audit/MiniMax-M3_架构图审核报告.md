| 项 | 内容 |

## 五、重点问题逐条回答（审核方点名 15 项，结论：11 项本来就对）

| 疑问 | 结论 |
|---|---|
| 专家数与激活数 | **128 专家 top-4 + 1 共享，正确**。「256 专家」是**上一代 M2.x 的配置**，属串代误记 |
| 激活参数量 | **23B 是 MiniMax 官方口径**。22B 出自 NVIDIA 自家文档（且与它自己的 Megatron-Bridge 页矛盾），25.2B 仅见第三方 → 图中无需改 |
| 前 3 层稠密 FFN + 12,288 | **正确**，config 的 `moe_layer_freq` 前 3 位为 0、`dense_intermediate_size: 12288` |
| 每个 query 最多接触 2,048 个 key token | **正确**，`sparse_topk_blocks 16 × sparse_block_size 128 = 2048`，NVIDIA 文档直接写出该乘积 |
| 索引头维度 128 / 每 GQA 组一个 / K 侧共享 | **三项均准确**（`sparse_index_dim: 128`、`sparse_num_index_heads: 4`） |

| partial RoPE 64/128 + θ=5e6 | **准确**（`rotary_dim: 64`、`rope_theta: 5000000`） |
| QK-Norm 按层→按头 | **准确**，M2 是 `per_layer`、M3 是 `per_head` |
| 许可证 | **MiniMax Community License 正确**；「MiniMax-Modified MIT」的说法不成立 |
| MTP 声明但无权重 | **准确**，NVIDIA 文档原文即如此描述 |
| 1/20、>9×、>15× | **官方原文，准确** |
| 「国内第一个齐备三项要素」 | **与官方中文原文几乎逐字一致** |

## 六、经核实确认无误的部分（摘）

- 总纲：≈428B / ≈23B · 60 层 · 128 路由专家 · 1M 上下文 · 2026-06-01 发布 · MiniMax Community License
- 词表 200,064、hidden 6,144、位置上限 1,048,576
- MSA 机制全部细节：块级 KV 选择、Index/Main 双分支、`KV outer gather Q`、比 Flash-Sparse-Attention / flash-moba 快 4 倍以上、「不把 KV 压进低维潜空间」
- GQA 64 query / 4 KV、16:1、head dim 128
- MoE 路由：Sigmoid + 专家偏置修正 + `routed_scaling_factor`（DeepSeek-V3 风格）、SwiGLU-OAI、Gemma 风格 RMSNorm
- MXFP8：≈440 GB、Blackwell / MI350X 硬件原生、旧卡加载时转 block-fp8 [128,128]、**视觉塔不量化**
- Thinking 三档 enabled / adaptive / disabled；推荐采样参数
- 左栏 2017 对照节点全部无事实问题

## 七、审核局限

1. **词表语言构成**：MiniMax 从未发布，图中已删去相关宣称。
2. **`license` 字段值**：官方页面标注 `minimax-community`，个别第三方页写 `other`，二者冲突 → 图中只保留许可证名称。
3. **部分机理解释属教学性推论**（如「一半维度承载位置、另一半保留内容表示」「按头归一化让尺度各自受控」）：官方只给配置值，未解释动机。这类表述在图中已按"解释性说明"处理。
4. **厂商自测口径**：性能与加速倍数均为官方自测，非第三方复现。
5. **⚠ 一条与图无关但值得留意的发现**：NVIDIA NeMo AutoModel 文档自身有两处错误——把 M3 的注意力写成「DSA」（DSA 是 DeepSeek 的机制），并把上下文写成「512k」。**应以 MiniMax 官方博客 + config.json + NVIDIA Megatron-Bridge 为准。**
